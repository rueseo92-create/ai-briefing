# 취향 엽서 (가칭)

내 취향을 모르는 사람을 위한 웰니스 iOS 앱. 매주 예산·에너지·시간을 묻고 거기에 맞는 작은 실험 세 장을 준다. 해 보고 사진과 느낌을 남기면 엽서 한 장이 되고, 구역마다 우표가 모인다.

> 취향은 질문에 답해서 생기지 않는다. 해 보고 → 느낌을 남기고 → 쌓일 때 보인다.

기획서: 「취향 엽서 기획서」(Claude Docs).

## 원칙

- **돈은 앱이 정하지 않는다.** 매주 "이번 주 얼마까지 쓸 수 있어요?"를 묻고, 그 안의 실험만 준다. 기본 카드의 절반 이상은 0원이다.
- **시간은 오가는 시간까지.** 40분 체험도 편도 50분이면 반나절 실험이다.
- **매번 다른 시도.** 세 장은 늘 서로 다른 구역에서 나오고, 한 장은 아직 우표가 없는 구역에서 온다. 해 본 것은 다시 안 나오고, 최근 3주 안에 보인 것도 다른 게 남아 있는 한 안 나온다. 넘긴 것은 한 달 쉰다.
- **추천은 "좋았던 이유"를 따라간다.** 조용해서 좋았던 차 시음 다음에 조용한 새벽 산책이 나올 수 있다.
- **별로인 것도 수확이다.** "다음엔 다르게" 도장이 찍힌 엽서도 엽서함에 남는다.
- **숙제가 아니다.** 측정, 연속 기록, 출석 체크 없음. 안 해도 엽서는 사라지지 않는다.
- **기록, 예산, 위치, 사진은 이 폰에만.** 공유하는 건 내가 고른 엽서 이미지와 취향 카드뿐.
- **광고는 솔직하게.** 항상 "광고" 표시, 한 번에 한 장, "결이 같은" 자리 금지, 싫어한 이유가 있으면 제외, 그 주 예산과 시간 안에서만.
- **건강을 약속하지 않는다.** 질병 예방·치료 효과를 말하지 않는다. 설정에 도움받을 곳(자살예방 상담전화 109)을 둔다.

## 기능 (v0.3)

| 탭 | 내용 |
|---|---|
| 엽서함 | 우표판(8구역, 좋았어요 3번이면 금색), 모은 엽서. 엽서를 누르면 뒷면(이유, 메모). 이미지로 저장·공유 |
| 이번 주 | 체크인(예산 · 에너지 · 시간 · 함께) → 실험 세 장(결이 같은 · 옆으로 한 칸 · 처음 가 보는). 카드마다 "실험 40분 · 오가는 시간 20분", "약 8,000원". "다른 걸로"는 이유를 물음 |
| 실험 | 설명, 시간, 비용, 장소. 광고면 원래 가격 → 혜택 뒤 가격과 코드, 키트면 구성·가격·주문 마감. "해 봤어요" → 느낌, 이유, 사진(앨범이나 카메라), 한 줄 메모 → 엽서 도착 |
| 주말 | 다가오는 토요일, 이번 주 예산 안의 키트, "○요일 낮 12시까지 주문하면 토요일에 받아요" |
| 나 | 엽서 5장부터 "나에게 온 편지"(취향 정리), 좋았던 이유, 구역별로 해 본 것, 취향 카드 공유, 설정 |

v0.3에서 더한 것:

| 기능 | 내용 |
|---|---|
| iCloud 백업 | 엽서, 사진, 기록을 **사용자 본인 iCloud의 비공개 데이터베이스**에 백업. 바뀌면 3초 뒤, 앱을 내릴 때 올린다. 새 폰에서 "iCloud에서 엽서 가져오기". "모두 지우기"는 백업도 지운다 |
| 알림 | 첫 체크인 뒤 한 번 묻는다. 월요일 9시 체크인, 키트 주문 마감 날 아침(마감 3시간 전), 토요일 10시 주말 계획. 기기 안에서만 |
| 날씨 | Apple 날씨(WeatherKit)로 동네의 이번 주 날씨. 바깥에 나가기 좋은 날(비 60% 미만, 0~33°C)이 2일 미만이면 "궂은 주"로 보고 실내 실험을 먼저 준다. 바깥 실험 카드에 "좋은 날: 수·토". 출처 표시 포함 |
| 계절 카드 | 카드 121장. 벚꽃, 수박 화채, 단풍, 첫눈처럼 그 계절에만 나오는 카드 |
| 문제 신고 | 실험 화면의 "문제가 있었나요?" → 문 닫힘·그런 곳 없음이면 그 장소를 다시 권하지 않는다. 메일로 장소 이름과 문제 종류만 보낼 수 있다 |
| 영업시간 안내 | 장소 카드에 "가기 전에 지도 앱에서 영업시간을 확인해 주세요" |
| 익명 주간 숫자 | 켠 사람만. 일주일에 한 번 체크인 여부, 엽서 수, 사진 넣은 수, 좋았어요 수, 바꾼 이유별 횟수, 혜택 코드 복사 수. 누가·무엇을·어디서는 없다(`WeeklyReportTests`가 확인) |

### 이번 주 체크인

| 질문 | 답 | 추천에 미치는 영향 |
|---|---|---|
| 얼마까지 쓸 수 있어요? | 0원 · 1만 원까지 · 3만 원까지 · 그 이상도 | 실제로 낼 돈(광고는 혜택 뒤 가격, 키트는 키트 가격)이 예산 안인 것만 |
| 에너지는요? | 낮음 · 보통 · 높음 | 낮음이면 20분 이하, 몸을 쓰지 않는 실험만 |
| 시간은요? | 짧게 · 반나절 · 하루 통째로 | 실험 + 오가는 시간이 30분 / 4시간 / 10시간 이내, 오가는 시간은 20분 / 1시간 / 3시간 이내 |
| 누구와요? | 혼자 · 누군가와 함께 | 혼자면 둘이 해야 하는 실험 제외, 함께면 함께하는 실험을 앞으로 |

- 지난번 답이 기본으로 잡혀 있다. 주중에 바꾸면 아직 안 한 카드 중 안 맞는 것만 바뀐다.
- "다른 걸로" → 돈이 들어서(더 싼 것 + 이번 주 예산 한 칸 낮춤) · 시간이 없어서(더 짧은 것) · 마음이 안 가서.

### 오가는 시간과 위치

| 장소 | 오가는 시간 |
|---|---|
| 집 | 0분 |
| 동네 어디서나(집 앞, 골목) | 카드마다 정해 둔 값 |
| 실제로 있어야 하는 곳(공원, 한강·천변, 숲길, 도서관, 캠핑장 등 21종) | Apple 지도에서 동네 근처를 찾아 가장 가까운 곳까지. 근처에 없으면 그 실험은 나오지 않는다 |
| 특정 장소(제휴처) | 그 장소까지 |

거리는 직선 거리 × 1.3 ÷ 이동 수단 속도 + 기다리는 시간, 왕복이다. 카드와 실험 화면에 실제 장소 이름과 작은 지도가 붙고, "이번 주" 왼쪽 위 지도 버튼(또는 설정)의 **동네 지도**에서 근처에 무엇이 있고 무엇이 없는지 볼 수 있다. 동네 장소는 처음 체크인할 때 찾고, 한 달이 지나거나 동네가 1.5km 넘게 바뀌면 다시 찾는다. 검색어와 동네 범위는 Apple 지도로 가지만 우리 서버로는 아무것도 가지 않는다.

위치는 사용자가 고른다: **동네만 고르기**(기본, 권한 없음, 서울 25개 구와 주요 도시) · **대략적 위치**(iOS reduced accuracy, 실험을 받을 때만) · **위치 없이**(집·동네 실험만). 어느 쪽이든 서버로 보내지 않는다. 이동 수단(걸어서 · 대중교통 · 차)은 한 번 묻는다.

## 비즈니스 모델

| 수익원 | 과금 | 예시 | 시작 |
|---|---|---|---|
| 체험 제휴(광고 실험) | 혜택 코드 사용 건당(성과형) | 첫 요가 수업 무료, 차 시음 40% 할인 | 출시 직후 |
| 주말 키트 | 제휴 판매 수수료 | 홈 티 시음, 족욕, 테라리움 | 출시 후 2~3달 |
| 실물 엽서 인쇄 | 장당·묶음 | 계절 엽서 8장, 연말 앨범, 친구에게 진짜 엽서 | 출시 후 3~4달 |
| 구독 | 월 구독 | 계절 리포트, 한 장 더 무제한, 엽서 테마 | 출시 후 6달 |
| 기업 복지 | 연간 계약 | 팀 웰니스 실험(개인 기록은 회사에 안 감) | 검토 |

- 광고와 키트는 그 주 예산 안에서만 보인다. 예산 0원이면 무료 혜택만.
- 체험 제휴는 그 주 시간 안에 실제로 오갈 수 있는 사람에게만 보인다. 동네 공방·스튜디오에 파는 포인트.
- 실물 상품은 Apple 인앱 결제 대상이 아니므로 외부 결제나 판매처 링크로 연결한다.
- 매출 공식과 지표는 기획서 참고. 먼저 볼 지표는 주간 실험 완료율, 사진 첨부율.

## 실행하기 (Mac)

Xcode 16 이상.

```bash
brew install xcodegen
xcodegen generate
open TasteLab.xcodeproj
```

서버 없이 예시 광고(지어낸 브랜드, 서울 안 대략적 좌표)와 예시 키트로 바로 돌아간다. 시뮬레이터에서 대략적 위치는 Features → Location으로 정할 수 있다.

핵심 로직 테스트(리눅스에서도 된다):

```bash
swift test --package-path Packages/TasteCore
```

## iCloud 백업, 익명 숫자, 날씨 켜기

모두 꺼진 채로도 앱은 돌아간다. 유료 Apple Developer 계정이 필요하다.

1. `project.yml`의 `PRODUCT_BUNDLE_IDENTIFIER`를 내 것으로 바꾸고 Xcode에서 Team을 고른다.
2. Signing & Capabilities → **iCloud**(CloudKit 체크, 컨테이너 생성)와 **WeatherKit**을 추가한다. Apple Developer 사이트의 App ID에서도 WeatherKit을 켠다.
3. `TasteLab/Model/Services.swift`의 `AppConfig.cloudKitContainer`에 컨테이너 이름을, `feedbackEmail`에 받을 주소를 넣는다.
4. 한 번 돌려 레코드가 생기면 CloudKit Console에서 확인한다.
   - 비공개 DB: `State`(file, updatedAt), `Photo`(image) — 사용자 본인만 본다
   - 공개 DB: `WeeklyReport`(week 외 숫자들) — 대시보드에서 `week`를 Queryable로 두고 주별로 모아 본다
5. 출시 전에 스키마를 Production으로 배포한다.

## 진짜 제안 연결하기

`TasteLab/Offers/OfferService.swift`의 `SampleOfferService`를 바꾼다. CloudKit 공개 데이터베이스에 제안(실험 + 장소 좌표 + 혜택 또는 키트)을 **운영자만 쓰고 앱은 읽기만** 하게 두고, 시·도 단위로 통째로 받아 기기 안에서 고른다.

## 구조

```
Packages/TasteCore/     # UI 없는 핵심 로직 + 테스트
  Taxonomy.swift        # 웰니스 구역 8개(우표 이름), 이유(태그) 12개
  Experiment.swift      # 실험(시간, 장소, 비용, 함께), 광고 혜택, 키트, 좌표
  CheckIn.swift         # 이번 주 체크인과 "할 수 있는지" 판단
  Travel.swift          # 위치 설정, 이동 수단, 오가는 시간
  Regions.swift         # 동네 목록(대략적 좌표)
  PlaceNeed.swift       # 실제로 있어야 하는 장소 21종과 검색어, 찾아 둔 동네 장소
  Catalog.swift         # 기본 실험 카드 121장(계절 카드 포함, 장소가 필요한 카드는 지도에서 확인)
  SampleOffers.swift    # 예시 광고 실험(장소 있음)과 키트
  Journal.swift         # 기록(엽서), 느낌 도장, 보여 준 것, 넘긴 것
  Stamps.swift          # 우표판, 금색 우표
  Profile.swift         # 취향 점수, 구역 상태, 취향 정리
  Recommender.swift     # 이번 주 세 장, 바꾸기(이유별), 주말 키트, 궂은 주엔 실내 먼저
  Week.swift            # 주 키, 요일, 계절
  Weather.swift         # 이번 주 날씨와 바깥에 나가기 좋은 날
  WeeklyReminders.swift # 월요일 체크인, 키트 마감, 주말 계획 알림 시각
  WeeklyReport.swift    # 익명 주간 숫자(허용된 필드만)
  Weekend.swift         # 키트 주문 마감과 도착 토요일
TasteLab/
  App/  Model/(상태, 서비스 약속, CloudKit 백업·숫자, 알림·날씨, 사진, 위치, 지도 검색)  Offers/  Design/  Views/
```
