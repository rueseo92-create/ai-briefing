# 취향 실험실 (Taste Lab)

내 취향을 모르는 사람을 위한 iOS 앱. 매주 작은 취향 실험 세 장을 받고, 해 본 뒤 10초만 느낌을 남기면 취향 지도가 조금씩 밝혀진다.

> 취향은 질문에 답해서 생기지 않는다. 해 보고 → 느낌을 남기고 → 쌓일 때 보인다.

## 원칙

- **추천은 "많이 본 것"이 아니라 "좋았던 이유"를 따라간다.** 조용해서 좋았던 카페 다음에 조용한 새벽 산책이 나올 수 있다. 분야를 넘나들어야 취향이 넓어진다.
- **매번 다른 시도.** 세 장은 늘 서로 다른 분야에서 나오고, 한 장은 아직 안 가 본 지역에서 온다. 해 본 실험은 다시 나오지 않고, 최근 3주 안에 보인 실험도 다른 게 남아 있는 한 나오지 않는다. 넘긴 실험은 한 달 쉰다.
- **별로인 것도 수확이다.** "별로였어요"도 지도에 남기고, 그 이유가 있는 실험은 덜 권한다.
- **숙제가 아니다.** 주 단위이고, 안 해도 아무 손해가 없다. 출석 체크, 연속 기록 압박 없음.
- **기록은 이 폰에만.** 공유하는 건 내가 고른 취향 카드뿐.
- **광고는 솔직하게.** 항상 "광고" 표시, 한 번에 많아야 한 장, "결이 같은" 자리에는 오지 않음, 싫어한 이유가 있는 광고는 나오지 않음. 고르는 일은 기기 안에서 하고, 광고주는 기록을 받지 않는다.

## 기능 (v0.1)

| 화면 | 내용 |
|---|---|
| 시작 | 앱 소개 3장, 광고 실험 받을지 선택 |
| 이번 주 | 실험 세 장: **결이 같은** · **옆으로 한 칸** · **처음 가 보는**. 카드마다 왜 권하는지 한 줄. "다른 걸로" 바꾸기, 다 하면 "한 장 더" |
| 실험 | 설명, 시간, 집/밖. 광고면 혜택 코드, 키트면 구성·가격·주문 마감. "해 봤어요" → 좋았어요/그저 그랬어요/별로였어요 + 이유 + 한 줄 메모 |
| 주말 | 다가오는 토요일, 나와 맞을 것 같은 키트, "○요일 낮 12시까지 주문하면 토요일에 받아요" |
| 취향 지도 | 8개 지역(소리, 맛과 향, 공간, 몸, 손, 사람, 글과 생각, 보는 것). 해 볼수록 밝아지고 "좋아하는 곳 / 나랑은 잘 안 맞음"이 드러남 |
| 취향 정리 | 5번 해 보면 열림. "조용한 것에 마음이 가는 사람" 같은 한 줄과 공통점, 아직 안 가 본 곳. 취향 카드 이미지로 저장·공유 |
| 기록 | 해 본 실험과 느낌 |

기본 실험 카드 64장(8개 지역 × 8장)은 모두 하루 안에, 돈을 거의 안 들이고 할 수 있는 것만 넣었다. 예시 광고 실험 3개, 예시 키트 6개가 들어 있다(브랜드 이름은 지어낸 것).

## 추천 방식

| 자리 | 고르는 법 |
|---|---|
| 결이 같은 | 좋았던 이유(상위 3개)가 들어 있는 실험 중 점수 상위 3개에서 하나 |
| 옆으로 한 칸 | 좋았던 이유 하나는 같고, 가장 익숙한 두 지역이 아닌 곳 |
| 처음 가 보는 | 가장 덜 가 본 지역에서. "나랑 안 맞음" 지역과 싫어한 이유가 있는 실험은 뺀다 |

- 점수 = 실험 태그별 점수 합 + 그 지역에서 좋았던 횟수 − 별로였던 횟수×2. 태그 점수는 좋았으면 +1, 고른 이유면 +2(별로면 반대).
- 늘 1등만 고르면 매번 같은 게 나오므로, 상위 셋 중에서 무작위로 고른다.
- 처음에는 좋았던 기록이 없으니 세 장 모두 서로 다른 지역에서 "처음 가 보는" 실험으로 준다.

## 비즈니스 모델

세 갈래로 번다. 앞의 둘은 "새로운 걸 해 보게 만든다"는 앱의 목적과 같은 방향이어서, 광고가 앱을 해치지 않고 실험 거리를 늘려 준다.

### 1. 광고 실험 (체험 제휴)
- 공방, 원데이 클래스, 클라이밍장, 찻집, 전시처럼 **처음 오는 손님이 필요한 곳**이 혜택(할인, 1+1, 무료 체험)과 함께 실험을 올린다.
- 과금: 혜택 코드가 실제로 쓰였을 때 받는 **성과형(CPA)**이 기본. 노출만으로 받는 고정 게재료는 큰 브랜드용 옵션.
- 측정: 광고주에게는 "코드가 몇 번 쓰였는지"만 전한다. 누가, 어떤 취향인지는 전하지 않는다.
- 왜 먹히나: 사용자는 이미 "이번 주에 뭔가 새로 해 볼" 마음으로 앱을 연다. 일반 광고보다 전환이 잘 날 수 있는 지점이다(가정, 검증 필요).
- 지켜야 할 것: 광고가 추천 품질을 해치면 앱 전체가 무너진다. 한 번에 한 장, "결이 같은" 자리 금지, 싫어한 이유 금지 규칙은 코드와 테스트로 묶어 두었다(`SponsoredTests`).

### 2. 주말 키트 배송
- "토요일에 자수 해 볼래요" → 수요일·목요일 마감 전에 주문하면 토요일 전에 키트가 온다.
- 처음에는 **제휴 판매(남의 재고)**로 시작한다. 공방·브랜드가 만들고 보내고, 앱은 주문을 연결하고 수수료를 받는다. 재고와 배송 부담이 없다.
- 반응이 좋은 키트가 보이면 그때 **자체 큐레이션 키트**(마진이 큰 대신 재고와 CS가 생김)를 검토한다.
- 실물 상품은 Apple 인앱 결제 대상이 아니므로 외부 결제(PG)나 판매처 링크로 연결한다.

### 3. 구독 (나중에)
- 취향 변화 리포트, 계절별 정리, 실험 무제한 "한 장 더", 친구와 취향 카드 비교 같은 것. 기본 기능(주 3장, 지도, 정리)은 계속 무료.

### 숫자로 보는 법 (가정)
실제 수치가 없으니 공식만 둔다. 출시 후 첫 달 데이터로 채운다.

- 광고 매출 = 주간 활성 사용자 × 광고 노출 비율 × 코드 사용률 × 건당 수수료
- 키트 매출 = 주간 활성 사용자 × 주말 키트 주문률 × 평균 주문 금액 × 수수료율
- 먼저 볼 지표: **주간 실험 완료율**(실험 세 장 중 하나라도 "해 봤어요"를 누른 사람 비율). 이게 낮으면 광고와 키트도 안 된다.

### 첫 제휴처 찾는 순서
1. 혼자 운영하는 공방·클래스 10곳에 직접 연락 (처음 손님이 필요하고 결정이 빠르다)
2. 키트를 이미 팔고 있는 소규모 브랜드 (DIY, 커피, 향, 식물)
3. 사용자 지도 데이터가 쌓이면(개인 정보 없이 지역별 "좋았어요" 비율만) 브랜드에 "이 분야를 처음 해 보는 사람이 많다"는 근거로 제안

## 실행하기 (Mac)

Xcode 16 이상.

```bash
brew install xcodegen
xcodegen generate
open TasteLab.xcodeproj
```

서버 없이 예시 광고와 키트로 바로 돌아간다.

핵심 로직 테스트 (리눅스에서도 된다):

```bash
swift test --package-path Packages/TasteCore
```

## 진짜 제안 연결하기

`TasteLab/Offers/OfferService.swift`의 `SampleOfferService`를 바꾼다. 서버를 따로 두지 않으려면 CloudKit 공개 데이터베이스에 `Offer` 레코드(실험 내용 + 광고 혜택 또는 키트 정보)를 **운영자만 쓰고 앱은 읽기만** 하게 둔다. 앱은 전부 받아 와서 기기 안에서 고른다.

## 구조

```
Packages/TasteCore/     # UI 없는 핵심 로직 + 테스트
  Taxonomy.swift        # 지역 8개, 이유(태그) 12개
  Experiment.swift      # 실험, 광고 혜택, 키트
  Catalog.swift         # 기본 실험 카드 64장
  SampleOffers.swift    # 예시 광고 실험과 키트
  Journal.swift         # 기록, 보여 준 것, 넘긴 것
  Profile.swift         # 취향 점수, 지도 상태, 취향 정리
  Recommender.swift     # 이번 주 세 장, 다른 걸로, 주말 키트
  Weekend.swift         # 키트 주문 마감과 도착 토요일
TasteLab/
  App/  Model/  Offers/  Design/  Views/
```
